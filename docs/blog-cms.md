# 每日碎念（/blog）內容發布說明

> 狀態（2026-10-06）：P0＋P1 頁面與內容契約已完成；**Notion 發布鏈尚未對真實資料庫驗證**。
> 規劃來源：Notion「emting.life 每日部落格｜頁面規劃與美感規格（2026-10-05）」。

## 內容怎麼進到網站

```
Notion 寫作／人工審核
  → scripts/sync-blog.ts（唯讀擷取 Published 文章、下載圖片）
  → src/content/blog/snapshot.json ＋ public/blog/media/*
  → build 時打包進伺服器端；請求時再過一次發布閘門
```

- Notion 是唯一的寫作來源。`snapshot.json` 是產生出來的快照，不要手改。
- 快照只存在伺服器端 bundle，不會進瀏覽器下載的 JS。
- 發布閘門（`src/lib/blog/posts.ts` 的 `isPublic`）：Published、已到 PublishedAt、未封存、校驗通過，四項都成立才公開。排程未到的文章在時間到之前回 404。

## 同步指令

```bash
NOTION_TOKEN=... NOTION_BLOG_DATABASE_ID=... node scripts/sync-blog.ts
```

- 需要 Node 22.18 以上（直接執行 TypeScript）。
- 權杖只放環境變數；不要寫進 `.env` 以外的檔案，也不要用 `VITE_` 開頭（會被打包進前端）。
- 仍在 Notion 的既有文章會預留原網址；若舊快照已有重複網址，整批同步會停止以避免資料不一致。
- 任何網路或權限錯誤都會整批中止，既有快照不變。 Notion 請求每次最多等待 15 秒；限流、伺服器錯誤和網路失敗最多重試至共 3 次。
- 圖片下載（含讀取內容）最多等待 15 秒；網路錯誤或逾時會中止整批並保留原快照。圖片若回傳 HTTP 錯誤、格式不支援或尺寸無法讀取，會標記該篇並列出區塊 ID；來源網址不會寫入錯誤訊息。
- 正文包含 `FINAL_CONTENT_BUNDLE.md`、`[web:數字]`／`[file:數字]` 引用標記或「【內部註記】」時，會在同步紀錄及內容 PR 提醒編輯者確認；原文保留，需人工判斷是否公開。
- 單篇含未支援內容時只阻擋那一篇，並印出標題、頁面 ID 與 block ID；結束碼為 2。成功轉換的文章仍寫進快照。
- 新快照與現有同步 PR 的文章和圖片完全相同時，不重複建立 PR；不同內容仍另開 PR，既有審核分支不會被改寫。
- 排程同步若結束碼為 2，仍會為已轉換的內容開 PR，並在內文列出被阻擋的文章；工作最後標成失敗，讓阻擋維持可見。結束碼 1（整批失敗）不開 PR，也不覆寫快照。

## Notion 資料庫欄位（提案，尚未建立）

| 欄位        | 型別           | 說明                                       |
| ----------- | -------------- | ------------------------------------------ |
| Title       | title          | 公開標題，純文字，不要埋換行               |
| Slug        | text           | 小寫英數與連字號；首次發布後網址凍結       |
| Topic       | select         | 身體／心情／靈命／家庭／事業／社會         |
| Status      | status         | Draft／Review／Published                   |
| PublishedAt | date（含時間） | 對外發布時間；網址日期取首次發布的台北日期 |
| Excerpt     | text           | 導讀；留空時用正文第一段                   |
| EpisodeURL  | url            | 相關集數連結；人工確認有關聯才填           |

## 指定公開正文

在 Notion 文章頁最外層新增一個摺疊區塊，標題只填 `【公開正文】`，將要發布的所有正文放在該區塊內。同步時只處理這個區塊內的內容與圖片；同層其他區塊視為製作資料，不會進入新快照。每頁只能有一個標記，標記不得為空；誤用一般段落作為標記時會阻擋同步。

未設定標記的既有文章維持原有整頁同步行為。要移除已公開的製作資料，仍須為該篇設定標記、重新同步並審核合併內容 PR。

## 正文支援的區塊

段落、H2／H3、粗體／斜體／行內程式碼、連結、項目與編號清單（可巢狀；同一項目底下可混用項目清單與編號清單，也可依序放段落、引文與程式碼）、引文、callout、圖片、表格、程式碼、分隔線、待辦事項（以勾選符號保留狀態）。toggle 與分欄會展開成一般內容。頁面、人員與其他行內 mention 會轉成顯示名稱的純文字，不另建 Notion 連結。

寫作慣例（由轉換層解讀，待主持人確認）：

- **引文來源**：在引文最後一行寫 `——來源`。
- **經文**：用 📖 圖示的 callout，最後一行寫 `——書卷 章:節（版本）`。缺出處會阻擋發布，經文內容不會被改寫。
- 內文若用了 H1，會整體降一級並在同步時提醒。

不支援、會阻擋該篇的內容：子頁面、資料庫、embed、Notion 內部連結。清單項目底下若不是巢狀清單、段落、引文、程式碼或分隔線（例如再放標題、圖片、callout），也會阻擋該篇。

## 網址

| 路徑                              | 用途                                                                                                             |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `/blog`                           | 首頁：精選、本週、六主題入口、列表                                                                               |
| `/blog/posts/[yyyy-mm-dd]-[slug]` | 單篇（紙感預設，可切夜讀）                                                                                       |
| `/blog/topic/[topic]`             | 六主題：body／mood／spirit／family／work／society，其他一律 404                                                  |
| `/blog/archive`                   | 封存，依年月分組；可用 `?topic=` 篩選主題、`?q=` 搜尋標題與摘要，`?month=` 篩選年月，`?page=` 翻頁（每頁 20 篇） |
| `/blog/week/[YYYY-Www]`           | 週索引（ISO 週）；格式錯誤、不存在或未來的週回 404                                                               |

沒有真實文章的主題頁、週索引與封存頁會標 `noindex`，也不會進 sitemap。

## 測試稿（fixtures）

`src/content/blog/fixtures/` 是打磨版面用的虛構內容，只在 `npm run dev` 時載入。
正式 build 不含測試稿，也不會出現在 sitemap。請勿從其他檔案靜態 import。
